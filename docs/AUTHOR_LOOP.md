# 作者写作与辅助校准：合成闭环

本轮从作者自己写正文出发：复制稿件、提出可核对的问题、由作者决定是否采纳。运行基底仍是 Oh Story；不恢复旧插件数据库，不把助手变成默认代写者。

## 可复跑

在仓库根目录运行：

```sh
node --test scripts/kaitu-author-loop.test.mjs
```

测试只在系统临时目录创建公开合成稿件，结束时清理自己的目录。不读取私人稿件，不连接模型，不调用付费 API。

## 复用这个窄检查器

作者在 DSH 中可直接使用 `/story-review`。遇到这一项适用关系并且作者明确确认条件时，助手可调用只读原生工具 `kaitu_check_declared_duration`；不需要作者运行程序。缺条件、没有工具或不适用时仍做普通审稿，不强制走这个核对。工具沿用 DSH 工具注册和参数校验，返回依据、结果和未改稿说明，不自动采纳。

下面是供开发者复用的独立纯函数模块，不是 CLI，也不是通用科学校对器。调用者必须先人工或通过模型提议、再经作者确认输入；下面使用合成的已确认数据：

```js
import { checkDeclaredDuration } from "./scripts/kaitu-duration-check.mjs";

const result = checkDeclaredDuration({
  rule: {
    confirmed: true, scope: "环廊匀速不停留", unit: "minute",
    minutesPerCycle: 8, quote: "环廊每圈恰好需要 8 分钟"
  },
  scene: {
    confirmed: true, scope: "环廊匀速不停留", unit: "minute",
    cycles: 2, elapsedMinutes: 19, constantDuration: true,
    extraDelayMinutes: 0, exception: "none",
    quote: "她不停留地匀速走了 2 圈，钟上过去了 19 分钟"
  }
});
// result.status === "conflict"; expectedMinutes === 16; observedMinutes === 19
// 不读写文件，不自动改正文。作者可以否决，也可以改变前提再检查。
```

不要用 `confirmed: true` 代替真实的作者确认。`not-checked` 不是“没有问题”，`consistent` 也只代表这一个算术关系吻合。测试实际调用同一个导出函数，不复制一个假实现。

## 实际验证的路径

1. 用现有 `prepareBook` 复制合成稿。逐字节校验作者原稿与导入副本相同，状态仅为 `copy-only`。
2. 人工明确抽取并确认本例的书内规则：“匀速行走且不停留时，每圈恰好 8 分钟”；正文“同条件下走 2 圈用了 19 分钟”。同一适用范围、同为分钟、没有额外耗时、没有例外。
3. 纯函数 `checkDeclaredDuration` 计算 `8 × 2 = 16`，报告与 19 的冲突，附输入引文和条件。它不读取正文、不抽取事实、不判断这些设定是否真实，也不自行核验引文与文件的对应。输入确认由调用者负责。
4. 报告给作者三个选择：改为 16 分钟；由作者解释额外 3 分钟并修改条件；保留原文待定。语法和创意建议另列为人工示例，不认作错误或正史。此时原稿和副本都未改。
5. 拒绝分支：不生成修订稿，原稿与副本 hash 保持不变。
6. 采纳分支：测试模拟作者**手动**选择仅改时间，另存到新建的 `修订副本/环廊-作者修订.md`；语法措辞与创意都不变。用 `wx` 禁止覆盖已有修订文件，再次校验两个原文件不变，并核对修订值符合原有规则。

这不是一个自动采纳接口。测试中的明确选择仅代表合成人工操作，不是用户给真实文件操作的授权，也不是对话权限系统的验证。

## 哪些可以硬检查

目前仅做一项实际需求：作者确认的正整数分钟/圈数乘法关系。量纲必须明确相同，适用范围相同，圈时恒定，额外耗时明确为 0，例外明确为无。

未知或未确认的条件、不同单位或范围、约数/小数、停留耗时、虚构例外、超出安全整数范围，全部返回“未检查”，不把它们误报为科学冲突。一个明确的虚构世界规则可以检查其内部算术一致性，但结果永远不证明现实世界的科学事实。

## 证据边界

| 层次 | 本轮状态 |
| --- | --- |
| 副本准备、原稿保留、算术核对、拒绝无改动、新副本采纳与禁止覆盖 | 自动测试实际执行 |
| 条件/引文抽取、作者是否认可规则、文学用法、科学真实性 | 本例人工给定，需作者或模型结合资料判断 |
| 语法和创意建议 | 人工编写演示，不是模型产出或质量结论 |
| Oh Story `/story-import` 的真实分析、分章、追踪初始化 | 本测试未执行，不能称“完整 AI 导入已通过” |
| 原生 DSH 对话的实际生成与作者点击采纳 | 本测试未执行；采纳路径只演示作者手动另存 |

需要真人创作验收时，在隔离副本里让 Oh Story 阅读作者明确给出的规则和本章，先只报告“依据、条件、疑点、备选”；作者选择后再另存修订稿。不要因为工程测试通过就宣布 AI 已理解全书、写得更好或科学推理正确。
